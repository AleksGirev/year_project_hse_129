## О проекте

Каждый день человек выбирает из десятков тысяч фильмов, а посмотреть успевает единицы. Рекомендательная система помогает с выбором: по прошлым оценкам пользователя она предлагает фильмы, которые ему, скорее всего, понравятся.

**Цель проекта** — построить рекомендательную систему, которая возвращает пользователю топ-N фильмов, и оформить её в виде веб-сервиса.

**Что будет на выходе:**

1. Исследование данных указанных датасетов с выводами о том, как пользователи ставят оценки.
2. Набор моделей от простых к более сложным и честное сравнение их качества на одних и тех же данных.
3. Сервис на FastAPI: по `user_id` он возвращает список рекомендованных фильмов, а новым пользователям показывает популярные фильмы.
4. Воспроизводимые эксперименты в MLflow и итоговая презентация.

**Как работает система (идея):**

```
История оценок пользователя ──► Модель ──► Оценка «насколько понравится»
                                           для каждого непросмотренного фильма
                                                      │
                                                      ▼
                                  Сортировка ──► Топ-10 рекомендаций
```

Если пользователь новый и оценок у него нет, система показывает популярные и высоко оценённые фильмы, а при выбранном жанре — лучшие фильмы этого жанра.

## Данные

**MovieLens 32M** — открытый датасет исследовательской группы GroupLens (Университет Миннесоты), собранный на сайте [movielens.org](https://movielens.org).

| Показатель | Значение |
|---|---|
| Оценок | 32 000 204 |
| Пользователей | 200 948 |
| Фильмов | 87 585 |
| Тегов | 2 000 072 |
| Период | 1995 – 2023 |
| Шкала оценок | от 0,5 до 5 с шагом 0,5 |

| Файл | Содержимое |
|---|---|
| `ratings.csv` | `userId, movieId, rating, timestamp` — оценки фильмов |
| `movies.csv` | `movieId, title, genres` — название с годом и жанры |
| `tags.csv` | `userId, movieId, tag, timestamp` — теги, которые пользователи ставят фильмам |
| `links.csv` | `movieId, imdbId, tmdbId` — ссылки на IMDb и TMDB |

Демографии пользователей в данных нет, у каждого пользователя не меньше 20 оценок. 

> Данные весят около 900 МБ и не хранятся в репозитории. Как их скачать, описано в разделе [Как запустить](#как-запустить).

Задачу можно решать двумя способами:

| Постановка | Что предсказываем | Метрики |

### Чекпоинт 3. Первые ML-модели

**Цель:** получить первые рабочие рекомендации и понять, какой подход работает лучше.

Промежуточные этапы:

0. Настройка [MLFlow](https://habr.com/ru/articles/908618/) для сохранения истории моделей для дальнейшего сравнения
1. **Выбор метрики.** Основная метрика — [NDCG@10](https://habr.com/ru/companies/econtenta/articles/303458/), дополнительные — RMSE, Precision@K, Recall@K и Coverage (см. [раздел о метриках](#постановка-задачи-и-метрики)). 
2. **Подготовка данных.** Вынести очистку из EDA в отдельный модуль, сделать разбиение на train/test и сохранить его, чтобы все модели сравнивались на одних и тех же данных.
3. **Бейзлайны без обучения:**
   - топ популярных фильмовы;
   - топ фильмов по сглаженной средней оценке;
4. **Классические модели:**
   - **Item-based KNN** — советуем фильмы, похожие на те, что пользователь уже высоко оценил;
   - **SVD (матричная факторизация)** — раскладываем матрицу оценок на «вкусы» пользователей и «характеристики» фильмов;
   - **ALS** — та же идея, но модель учится на самом факте взаимодействия (оценил или нет) и сразу нацелена на ранжирование.
5. **Улучшение за счёт работы с данными.** Проверить, как на качество влияют фильтрация редких фильмов и пользователей, сглаживание средних.
6. **Подбор гиперпараметров.** Число латентных факторов, регуляризацию и число соседей подбираем на валидационной выборке.
7. **Выводы.** Сводная таблица метрик всех моделей и несколько примеров рекомендаций для реальных пользователей.

### Чекпоинт 4. ML-сервис

**Цель:** сделать так, чтобы лучшей моделью можно было пользоваться не только в ноутбуке.

Промежуточные этапы:

1. **Инференс.** Сохранить обученную модель и справочник `movieId → название` в файлы, загружать их при старте сервиса.
2. **Приём данных и возврат результата.** Написать API на **FastAPI**:

   | Метод | Описание |
   |---|---|
   | `GET /health` | Проверка, что сервис работает |
   | `GET /recommend/{user_id}?k=10` | Топ-K фильмов для пользователя |
   | `POST /recommend/new_user` | Рекомендации по нескольким оценкам нового пользователя |
   | `GET /movies/{movie_id}/similar` | Похожие фильмы |
   | `GET /popular?genre=Comedy` | Популярные фильмы, в том числе по жанру |

3. **Формат ответа.** Описать формат запросов и ответов через **Pydantic** (список фильмов с `movieId`, названием, жанрами и предсказанной оценкой) и обработать ошибки (неизвестный пользователь или фильм).

### Чекпоинт 5. Улучшение ML-модели

**Цель:** улучшить качество рекомендаций за счёт более сложных моделей, новых признаков и данных.

Промежуточные этапы:

1. **Работа с признаками.** Жанры, год выпуска, теги, сглаженные средние и счётчики пользователя и фильма.
2. **Увеличение данных.**
   - подтянуть описания и жанры фильмов из TMDB по `tmdbId`, заполнить пропуски жанра и года, найденные в EDA;
   - повторить лучшие модели на [KION](https://github.com/irsafilo/KION_DATASET) и проверить, сохраняется ли их порядок по качеству;
   - (Возможно) Тексты отзывов из Amazon Reviews 2023 (категория Movies & TV) как дополнительный источник признаков.
3. **Более сложные модели:**
   - контентная модель — рекомендации по похожести фильмов;
   - (Возможно) двухэтапная схема — ALS + CatBoost( отбор N кандидатов, переупорядочивание их с учётом признаков).
4. **Анализ результатов.** Сравнить новые модели с моделями из чекпоинта 3, проверить, насколько модель «залипает» на популярных фильмах, обновить модель в сервисе.

### Чекпоинт 6. Нейронные сети

**Цель:** проверить, дают ли нейросети выигрыш на этой задаче.

Промежуточные этапы:

1. **Простая эмбеддинг-модель на PyTorch.** Векторы пользователя и фильма и их скалярное произведение — по сути нейросетевой аналог SVD.
2. **Neural Collaborative Filtering (NCF).** К эмбеддингам добавляются полносвязные слои.
3. **Трансформеры для последовательностей (SASRec, BERT4Rec).** Модель смотрит на историю пользователя как на последовательность фильмов и предсказывает следующий. [В статье от MTS](https://habr.com/ru/companies/ru_mts/articles/947710/) есть готовые тулзы - [RecTools](https://github.com/MobileTeleSystems/RecTools).
4. **Эмбеддинги текстов.** Готовая предобученная модель [BGE-M3](https://huggingface.co/BAAI/bge-m3) (либо что-то легче), загруженная через библиотеку `sentence-transformers`, переводит описания фильмов в векторы (1024 числа на фильм):.
5. **Сравнение архитектур между собой**: простая эмбеддинг-модель, NCF, SASRec / BERT4Rec.
6. **Сравнение с классическими ML-подходами** из чекпоинтов 3 и 5 по качеству, времени обучения и скорости ответа.
7. **Выводы.** Стоит ли нейросеть усложнения; визуализация эмбеддингов фильмов (t-SNE или UMAP) — группируются ли похожие фильмы.

### Чекпоинт 7. Финальные доработки

**Цель:** сделать проект воспроизводимым и понятным внешнему читателю.

Промежуточные этапы:

1. **Настройка MLflow:** логировать параметры и метрики всех экспериментов.
2. **Воспроизводимость:** фиксированные `random_state`, версии библиотек в `requirements.txt`, сохранённое разбиение данных.
3. **Переобучение и логирование лучшей модели** на полных данных.
4. **Сохранение артефактов:** модель, справочники и графики — в MLflow.
5. **Анализ ошибок:** для каких пользователей и фильмов модель работает хуже (новые пользователи, редкие фильмы, отдельные жанры).
6. **Анализ устойчивости:** как меняется качество на разных периодах времени и при разных случайных разбиениях.
7. Обновить README и привести код в порядок. *По желанию:* собрать сервис в Docker.
